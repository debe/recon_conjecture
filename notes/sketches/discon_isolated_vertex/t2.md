# Sketch t2: discon_isolated_vertex, counting route with minimal plumbing

Status: **sketch**. Nothing here is a result; the Lean gate is the only judge.
Author label: t2. Angle: edge counting to move the isolated vertex across the hypomorphism,
then extend the card isomorphism by one point.

Step record read first (`desk.py status discon_isolated_vertex`): frozen, approved,
`dead_ends` is empty, no earlier sketches. Nothing to avoid.

## 0. Statement, unfolded

```lean
Recon.ClassReconstructible (fun n G => ∃ v : Fin n, ∀ w : Fin n, ¬ G.Adj v w)
```

For all `n ≥ 3`, all `G H : SimpleGraph (Fin n)`: if some `v` has no neighbour in `G`, and
`σ : Fin n ≃ Fin n` satisfies `card G x ≃g card H (σ x)` for every `x`, then `G ≃g H`.

Note `SimpleGraph.IsIsolated G v` is by definition `∀ w, ¬ G.Adj v w`
(`Combinatorics/SimpleGraph/Basic.lean:1038`), so the class predicate is `∃ v, G.IsIsolated v`
up to unfolding. The route below never needs that name.

## 1. Paper argument

Let `v` be isolated in `G`, let `σ` be the hypomorphism and put `w := σ v`. Let
`e : G − v ≅ H − w` be the card isomorphism that `σ` supplies at `v`.

1. **Edge count transfers.** `|E(G)| = |E(H)|` because `n ≥ 3`
   (`kelly_edge_count`, checked on `main`).
2. **Card edge count transfers.** `|E(G − v)| = |E(H − w)|`, because `e` is an isomorphism.
3. **Degree identity.** `|E(G − x)| + deg_G(x) = |E(G)|` for every graph and vertex
   (`kelly_card_edges_add_degree`, checked on `main`). Apply it to `(G, v)` and `(H, w)`.
4. **Arithmetic.** `deg_G(v) = 0`, so `|E(G − v)| = |E(G)|`, so
   `|E(H − w)| = |E(H)|`, so `deg_H(w) = 0`. Hence `w` is isolated in `H`.
5. **Extension.** Define `f : V(G) → V(H)` by `f v = w` and `f x = e x` for `x ≠ v`. It is a
   bijection because `e` is a bijection `V(G) ∖ {v} → V(H) ∖ {w}`. It preserves adjacency:
   - on pairs avoiding `v` this is `e`;
   - on pairs containing `v` both sides are false, since `v` is isolated in `G` and `w` is
     isolated in `H`.
   So `f : G ≅ H`.

About the angle's phrase "every card with the maximum edge count comes from an isolated
vertex": that is the deck-level paraphrase of steps 3–4 (a card has at most `|E|` edges, with
equality exactly at isolated vertices). In the repo's bijection formulation of `Hypomorphic`
there is no need to pick a maximum: `σ` already hands over the partner card `H − σ v`, and
steps 1–4 say its deleted vertex is isolated. No `Finset.max`, no argmax, no multiset of
cards.

Source. This is the trivial case of Kelly's theorem that disconnected graphs are
reconstructible: P. J. Kelly, "A congruence theorem for trees", *Pacific J. Math.* 7 (1957)
961–968 (citation as confirmed in `notes/literature/found_hypomorphism_basics.md`, [Kel57]).
The isolated-vertex special case with this exact argument is folklore; I did not find a
source that states it separately, and the argument above does not rely on one: every step is
either a checked library fact or elementary.

## 2. Where `n ≥ 3` and finiteness enter

- `n ≥ 3` is used **only** in step 1. At `n = 2` the statement is false: `2K₁` has an
  isolated vertex and is hypomorphic to `K₂` (anchor `anchor_two_vertices_hypomorphic`).
  The small-graph tool finds exactly this pair when run with `--n-min 2 --n-max 2`.
- Finiteness is used in steps 1, 3 and 4 (cancellation of finite edge counts; `ncard = 0`
  implies empty only for finite sets). The extension step 5 needs no finiteness at all.

### 3.1 Lemma A: one-point extension of an Equiv

```lean
def extendEquiv {V W : Type*} [DecidableEq V] [DecidableEq W] (v : V) (w : W)
    (e : ({v}ᶜ : Set V) ≃ ({w}ᶜ : Set W)) : V ≃ W
```

Four ways to build it were probed. Recommendation: **A1 (hand-built `dite`)**.

| Route | Construction | Verdict from the probe |
|---|---|---|
| **A1** | `toFun x := if h : x = v then w else (e ⟨x, h⟩ : W)`, `invFun` symmetric | elaborated first try; works for different vertex types `V`, `W`; no finiteness; the two unfolding facts `f v = w` and `f x = e ⟨x, hx⟩` are closed by `simp [extendEquiv, hx]` |
| A2 | `Equiv.extendSubtype` (`Logic/Equiv/Fintype.lean:135`) with `extendSubtype_apply_of_mem` (:138) and `extendSubtype_not_mem` (:150) | elaborated; needs `[Finite V]`, same type on both sides (fine for `Fin n`), and explicit `(p := fun x => x ∈ ({v}ᶜ : Set V)) (q := …)` at every use because unification does not see the predicate through the `Set` coercion; `f v = w` comes from `extendSubtype_not_mem` + `simpa` |
| A3 | `(Equiv.optionSubtypeNe v).symm.trans ((Equiv.optionCongr e').trans (Equiv.optionSubtypeNe w))` (`Logic/Equiv/Option.lean:243`; `Equiv.optionSubtype` is at :154) | elaborated after one repair: `f x = e ⟨x, hx⟩` needed `simp [f, e', Equiv.optionSubtypeNe_symm_of_ne hx]` followed by `rfl`; also needs a `let e' : {b // b ≠ v} ≃ {b // b ≠ w} := e.toEquiv` to recast `↥({v}ᶜ : Set V)` as `{b // b ≠ v}` (definitional, not syntactic) |
| A4 | `Equiv.ofBijective f (Finite.injective_iff_bijective.mp hinj)` with only injectivity argued | elaborated; needs `[Finite V]` and same type; longest of the four |

Why A1: it is the only route with no hidden coercion between `↥({v}ᶜ : Set V)` and
`{b // b ≠ v}` or `{x // p x}`, and `simp` unfolds it directly. `Equiv.optionSubtype`
(named in the angle) is usable but buys nothing here: the `Option` detour adds a recast and
a `casesOn'` term that `simp` does not fully normalise.

Key technical fact that makes A1 painless: for `h : ¬ x = v`, the term `⟨x, h⟩` is accepted
as an element of `↥({v}ᶜ : Set V)` (membership in `{v}ᶜ` unfolds to `¬ x = v`). For
`left_inv` one needs `(e ⟨x, h⟩ : W) ≠ w`, obtained from `(e ⟨x, h⟩).2` after
`simp only [Set.mem_compl_iff, Set.mem_singleton_iff]`.

### 3.2 Lemma B: extension of a card isomorphism

General form (recommended, same cost, reusable for the `regular` program where the deleted
vertex is re-attached to prescribed neighbours):

```lean
theorem extendIsoGen {V W : Type*} {G : SimpleGraph V} {H : SimpleGraph W} {v : V} {w : W}
    (e : Recon.card G v ≃g Recon.card H w)
    (hN : ∀ (x : V) (hx : x ≠ v), H.Adj w (e ⟨x, hx⟩) ↔ G.Adj v x) : Nonempty (G ≃g H)
```

Isolated case is `extendIsoGen e (fun x _ => iff_of_false (hw _) (hv x))`.

Proof shape: `refine ⟨⟨extendEquiv v w e.toEquiv, ?_⟩⟩; intro a b`, then
`by_cases ha : a = v <;> by_cases hb : b = v`:
- both equal: `subst`, `simp [extendEquiv]` (both sides are loops);
- exactly one equal: `subst`, then `simpa [extendEquiv, hb] using hN b hb` (use `adj_comm` on
  both sides for the mirrored case);
- neither: `simpa [extendEquiv, ha, hb] using e.map_rel_iff (a := ⟨a, ha⟩) (b := ⟨b, hb⟩)`.

`Recon.card` is an `abbrev` for `G.induce {x}ᶜ`, and `induce_adj` is `.rfl`
(`Combinatorics/SimpleGraph/Maps.lean:316`), so `e.map_rel_iff` is already the statement
about `G.Adj` and `H.Adj` on the underlying vertices; `simp` gets there through
`SimpleGraph.comap_adj` (`Maps.lean:136`).

### 3.3 Lemma C: the partner vertex is isolated

Inside the main theorem, with `e : card G v ≃g card H (σ v)`:

```lean
have hE := Recon.Checked.L_kelly_edge_count n hn G H ⟨σ, hσ⟩
have hG := Recon.Checked.L_kelly_card_edges_add_degree n G v
have hH := Recon.Checked.L_kelly_card_edges_add_degree n H (σ v)
have hc := Recon.Checked.L_kelly_edge_count.ncard_eq_of_iso e
```

- `G.neighborSet v = ∅` by `ext x; simp [hv x]`, then `rw [hGv, Set.ncard_empty] at hG`.
- `(H.neighborSet (σ v)).ncard = 0` by `omega` from `hE hG hH hc`.
- `H.neighborSet (σ v) = ∅` by `Set.ncard_eq_zero (Set.toFinite _)`
  (`Data/Set/Card.lean:697`).
- `∀ y, ¬ H.Adj (σ v) y`: membership `y ∈ H.neighborSet (σ v)` is `H.Adj (σ v) y`
  definitionally (`mem_neighborSet`, `Basic.lean:808`), so rewrite with the empty set.

`ncard_eq_of_iso` is a helper inside the checked file `L_kelly_edge_count.lean`
(`G.edgeSet.ncard = H.edgeSet.ncard` from `e : G ≃g H`, any vertex types). If importing a
helper from another checked file is unwanted, its body is two lines:
`rw [← Nat.card_coe_set_eq, ← Nat.card_coe_set_eq]; exact Nat.card_congr e.mapEdgeSet`
(`Iso.mapEdgeSet`, `Maps.lean:774`).

### 3.4 Skeleton that elaborated in the probe

```lean
import Mathlib
import Recon.Statements.S_discon_isolated_vertex
import Recon.Checked.L_kelly_edge_count
import Recon.Checked.L_kelly_card_edges_add_degree

namespace Recon.Checked.L_discon_isolated_vertex

open SimpleGraph

def extendEquiv {V W : Type*} [DecidableEq V] [DecidableEq W] (v : V) (w : W)
    (e : ({v}ᶜ : Set V) ≃ ({w}ᶜ : Set W)) : V ≃ W where
  toFun x := if h : x = v then w else (e ⟨x, h⟩ : W)
  invFun y := if h : y = w then v else (e.symm ⟨y, h⟩ : V)
  left_inv x := by
    by_cases h : x = v
    · simp [h]
    · have := (e ⟨x, h⟩).2
      simp only [Set.mem_compl_iff, Set.mem_singleton_iff] at this
      simp [h, this]
  right_inv y := by
    by_cases h : y = w
    · simp [h]
    · have := (e.symm ⟨y, h⟩).2
      simp only [Set.mem_compl_iff, Set.mem_singleton_iff] at this
      simp [h, this]

theorem extendIsoGen {V W : Type*} {G : SimpleGraph V} {H : SimpleGraph W} {v : V} {w : W}
    (e : Recon.card G v ≃g Recon.card H w)
    (hN : ∀ (x : V) (hx : x ≠ v), H.Adj w (e ⟨x, hx⟩) ↔ G.Adj v x) : Nonempty (G ≃g H) := by
  classical
  refine ⟨⟨extendEquiv v w e.toEquiv, ?_⟩⟩
  intro a b
  by_cases ha : a = v <;> by_cases hb : b = v
  · subst ha; subst hb; simp [extendEquiv]
  · subst ha
    simpa [extendEquiv, hb] using hN b hb
  · subst hb
    have := hN a ha
    rw [adj_comm, adj_comm G] at this
    simpa [extendEquiv, ha] using this
  · have := e.map_rel_iff (a := ⟨a, ha⟩) (b := ⟨b, hb⟩)
    simpa [extendEquiv, ha, hb] using this

end Recon.Checked.L_discon_isolated_vertex

theorem Recon.Checked.L_discon_isolated_vertex : Recon.Statements.S_discon_isolated_vertex := by
  intro n hn G ⟨v, hv⟩ H ⟨σ, hσ⟩
  obtain ⟨e⟩ := hσ v
  have hE := Recon.Checked.L_kelly_edge_count n hn G H ⟨σ, hσ⟩
  have hG := Recon.Checked.L_kelly_card_edges_add_degree n G v
  have hH := Recon.Checked.L_kelly_card_edges_add_degree n H (σ v)
  have hc := Recon.Checked.L_kelly_edge_count.ncard_eq_of_iso e
  have hGv : G.neighborSet v = ∅ := by
    ext x; simp [hv x]
  rw [hGv, Set.ncard_empty] at hG
  have hdeg : (H.neighborSet (σ v)).ncard = 0 := by omega
  have hHv : H.neighborSet (σ v) = ∅ := by
    rwa [Set.ncard_eq_zero (Set.toFinite _)] at hdeg
  have hw : ∀ y, ¬ H.Adj (σ v) y := fun y hy => by
    have : y ∈ H.neighborSet (σ v) := hy
    rw [hHv] at this
    exact this
  exact Recon.Checked.L_discon_isolated_vertex.extendIsoGen e
    (fun x _ => iff_of_false (hw _) (hv x))
```

## 5. Small-graph evidence (evidence only)

Claim file: `notes/sketches/discon_isolated_vertex/claim_t2.py`.

- `claim(G)`: a card has `|E(G)|` edges iff its deleted vertex is isolated; cards at
  isolated vertices are pairwise isomorphic.
- `claim_pair(G, H)` on hypomorphic pairs: equal edge counts; `G` has an isolated vertex iff
  `H` has one; card iso at isolated vertices implies `G ≅ H`.
- Result: `NO WITNESS after 2498 checks (exhaustive n=3..7)`.
- With `--n-min 2 --n-max 2` the tool reports the witness `2K₁` vs `K₂`, as expected: the
  `3 ≤ n` guard is load-bearing and the test is not vacuous.
- Because hypomorphic pairs for `n ≤ 7` are all isomorphic, `claim_pair` exercises little.
  The file therefore also has `_all_pairs_check` (run with
  `PYTHONPATH=tools/search python3 notes/sketches/discon_isolated_vertex/claim_t2.py`): over
  **all** pairs `(G, H)` on `n ≤ 6` vertices with `|E(G)| = |E(H)|`, every isolated `v` of
  `G` and every `w` of `H` with `G − v ≅ H − w`, it checks that `w` is isolated in `H` and
  `G ≅ H`. This is exactly what steps 2–5 use after step 1. Result: `NO WITNESS`, 207
  matching configurations.

## 6. Where it could break

1. **Paper level.** I see no gap. Steps 1 and 3 are checked library facts; step 4 is
   natural-number arithmetic; step 5 is a four-case check.
2. **Lean level, the dependent `if`.** `simp` must reduce `dite` under the hypotheses
   `ha : ¬ a = v`. In the probe `simp [extendEquiv, ha, hb]` did it. If a future `simp` set
   leaves `dite` terms, fall back to `rw [dif_neg ha]` / `dif_pos rfl` after
   `show`-unfolding `extendEquiv`, or use `split_ifs`.
3. **`subst` direction.** `subst ha` with `ha : a = v` eliminates one of the two variables;
   either is fine in Lemma B because `v` is a variable there. Do not `subst` inside the main
   theorem where `σ v` appears.
4. **Importing a helper from another checked file.** `ncard_eq_of_iso` lives in the
   namespace of `L_kelly_edge_count`. The gate allows imports of `Recon.Checked.*`; if the
   audit objects to using a non-headline declaration, inline it (two lines, section 3.3).
5. **Decidability.** `extendEquiv` takes `[DecidableEq V] [DecidableEq W]`; `Fin n` has it,
   and `classical` inside Lemma B supplies it in general. No `Fintype`, `DecidableRel` or
   `edgeFinset` appears anywhere, which is the point of staying with `Set.ncard`.
6. **Forbidden tokens.** No `instance`, `structure`, `notation`, or `#` is needed. `def …
   where` is fine (the checked `cardIso` uses it).

## 7. What breaks for tournaments, hypergraphs, infinite graphs

- **Digraphs / tournaments (Stockmeyer 1977, 1981).** The same argument would go through for
  digraphs with a vertex of in- and out-degree 0 (arc count is recognizable for `n ≥ 3` by
  the same double count). That is consistent with Stockmeyer: a tournament on at least two
  vertices has no such vertex. So this route does not contradict the known failures; it
  just says nothing about them.
- **k-uniform hypergraphs (Kocay 1987).** Same remark: the argument transfers to hypergraphs
  with an isolated vertex once the edge count is recognizable, so it implies that no
  non-reconstructible hypergraph of that kind has an isolated vertex. I did not check
  Kocay's examples against this (UNVERIFIED); it is not needed for the step.
- **Infinite graphs (Fisher 1969; Bowler et al. 2017).** Steps 1, 3, 4 use cancellation of
  finite cardinals and fail for infinite edge sets (`Set.ncard` of an infinite set is `0`,
  and the checked dependencies are stated for `Fin n` only). The route correctly does not
  extend. I did not look for an infinite counterexample with an isolated vertex.
- **n = 2.** Fails at step 1 only, matching the anchor.

## 8. Verdict

Route. Short, finite, no missing Mathlib theory; the two counting facts it needs are already
checked on `main`, and the only new construction is a ten-line `Equiv`. Formalization risk:
low. Reusable by-product: `extendEquiv` and `extendIsoGen` (general re-attachment of a deleted
vertex), which the `regular` program needs in the same form.
